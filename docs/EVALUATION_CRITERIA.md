# EVALUATION_CRITERIA.md

> Evaluator が使う評価基準です。
> この基準に照らして合格 / 不合格を判定します。
> 「概ね良い」「小さい問題だからOK」は禁止です。

---

## 評価の基本方針

- Playwright MCP でブラウザを実際に操作して確認する
- コードを読むだけでなく、実際の動作を確認する
- スタブ・仮実装・見た目だけの実装は不合格
- 1 つでも必須項目を満たさなければ不合格

---

## 1. 機能性

### 1-1. ユーザーが目的を達成できるか

| 確認項目 | 合格基準 | 確認方法 |
|---|---|---|
| 主要フローが完結する | ユーザーが主要操作を最初から最後まで実行できる | Playwright で操作する |
| データが保存・反映される | 入力したデータが画面に反映される | 入力後の状態を確認 |
| 遷移・リダイレクトが動作する | ボタン押下後に適切な画面に移動する | クリック後のURLを確認 |

### 1-2. 主要操作が実際に動作するか

| 確認項目 | 合格基準 | 確認方法 |
|---|---|---|
| ボタンがクリックできる | クリック後に何かが起きる（変化がある）| Playwright でクリック |
| フォームが送信できる | 送信後にレスポンスがある | 送信後の状態を確認 |
| 入力欄に入力できる | キーボード入力が反映される | Playwright で type |

### 1-3. スタブや未接続の機能がないか

| 確認項目 | 合格基準 | 確認方法 |
|---|---|---|
| console.log で代替していない | 実際の処理が実装されている | コードとブラウザ両方で確認 |
| `TODO` `FIXME` が残っていない | 実装済みの状態 | コードを grep |
| ダミーデータのみではない | 実データまたは適切な初期状態がある | 画面を確認 |

## 2. UI 品質

### 2-1. 見た目が破綻していないか

| 確認項目 | 合格基準 | 確認方法 |
|---|---|---|
| 要素が重なっていない | すべての要素が適切な位置に表示される | 画面確認 |
| テキストが読める | 背景色と文字色のコントラストが確保されている | 画面確認 |
| ボタンが押せる見た目をしている | クリック可能な要素が視覚的に分かる | 画面確認 |

### 2-2. 余白・色・文字サイズが自然か

| 確認項目 | 合格基準 | 確認方法 |
|---|---|---|
| 適切な余白がある | 要素が詰まりすぎていない | 画面確認 |
| 文字サイズが読みやすい | 本文は 14px 以上 | 画面確認 |
| 色使いが統一されている | 無秩序な色使いではない | 画面確認 |

### 2-3. スマホ表示で崩れないか

| 確認項目 | 合格基準 | 確認方法 |
|---|---|---|
| 375px 幅で崩れない | レイアウトが維持される | Playwright viewport 設定 |
| 横スクロールが発生しない | body の幅が viewport 内に収まる | Playwright で確認 |
| ボタンが押せる大きさがある | 最小 44px のタップ領域 | 画面確認 |

## 3. エラー耐性

### 3-1. 入力ミスや失敗時に壊れないか

| 確認項目 | 合格基準 | 確認方法 |
|---|---|---|
| 空入力で送信してもクラッシュしない | エラーメッセージが表示されるか、何も起きない | Playwright で空送信 |
| 不正入力でクラッシュしない | エラーメッセージが表示される | Playwright で不正値入力 |
| ページがフリーズしない | 操作後もページが応答する | Playwright で操作 |

### 3-2. ユーザーに分かるエラー表示があるか

| 確認項目 | 合格基準 | 確認方法 |
|---|---|---|
| エラーメッセージが日本語で表示される | 「〇〇は必須です」など具体的なメッセージ | Playwright でエラー誘発 |
| エラー状態が視覚的に分かる | 赤枠・赤文字など | 画面確認 |

### 3-3. ブラウザ API が使えない場合でも落ちないか

| 確認項目 | 合格基準 | 確認方法 |
|---|---|---|
| localStorage アクセスで try/catch がある | クラッシュしない | コード確認 |
| SSR 環境で window/document を直接参照していない | ビルドエラーが出ない | build 確認 |

## 4. 実装品質

### 4-1. TypeScript の型が適切か

| 確認項目 | 合格基準 | 確認方法 |
|---|---|---|
| `any` を使っていない | 型が明示されている | `grep -r "any" src/` |
| 型エラーが 0 件 | `npm run build` が通る | build 実行 |
| Props 型が定義されている | コンポーネントに型がある | コード確認 |

### 4-2. 不要な依存関係を追加していないか

| 確認項目 | 合格基準 | 確認方法 |
|---|---|---|
| `package.json` の変更が最小限 | TASK に必要な変更のみ | `git diff package.json` |
| 未使用の import がない | import が使われている | コード確認 |

### 4-3. 大規模リファクタリングをしていないか

| 確認項目 | 合格基準 | 確認方法 |
|---|---|---|
| 変更ファイルが TASK のスコープ内 | 無関係なファイルが変更されていない | `git diff --name-only` |
| 既存コードの大量書き換えがない | TASK に関係する部分のみ変更 | `git diff` |

---

## 5. タスク分離

### 5-1. 1 TASK の範囲を超えていないか

| 確認項目 | 合格基準 | 確認方法 |
|---|---|---|
| 1 TASK で複数 TASK を実装していない | commit が 1 TASK 分の変更 | `git diff` |
| 将来機能を先に実装していない | MVP_TASKS.md の範囲内 | TASK 定義と照合 |

### 5-2. commit が 1 TASK 単位になっているか

| 確認項目 | 合格基準 | 確認方法 |
|---|---|---|
| commit が 1 件（またはレビュー後に追加修正した分）| 適切な粒度 | `git log --oneline` |
| commit メッセージが TASK ID を含む | `TASK-XXX:` のフォーマット | `git log` |

### 5-3. ドキュメントが実態と一致しているか

| 確認項目 | 合格基準 | 確認方法 |
|---|---|---|
| `STATUS.md` が更新されている | 完了 TASK が反映されている | ファイル確認 |
| `MVP_TASKS.md` のステータスが更新されている | `[x]` または `[!]` になっている | ファイル確認 |
