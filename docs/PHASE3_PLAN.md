# PHASE3_PLAN.md — Phase 3: ログイン不要テストモード + 高度な日程調整フロー

作成日: 2026-06-11

---

## アプリの目的（Phase 3 追加分）

既存の農園ゲーム（Phase 2、ログイン必須）と共存する形で「ログイン不要のテストモード」を追加する。
キャラクターをタップしてからの送信〜確定〜返信サイクルを、より使いやすい日程入力UI・状態管理・通知フローで実現する。

---

## 対象ユーザー

| ユーザー | 属性 | 利用シーン |
|---|---|---|
| 送信者（学生） | 農園でキャラをタップする人。ログイン不要モードでは URL に farm_contact_id が埋め込まれた URL を直接開く | キャラをタップして相談リクエストを送りたい |
| 受け取る側（先生など） | ログイン不要。固有URLを開いて返信・確定する | 学生から届いたURLを開いてミーティングを確定 or 別日を提案したい |

---

## Phase 3 の概念モデル

```
[ログイン不要モードの農園]
  キャラをタップ
    ↓
  /demo/request/[farm_contact_id] — 送信フォーム（名前・相談内容・希望日程）
    ↓ 送信
  URL生成 → 送信確認画面（今送る / 後で）
    ↓ 今送る
  URLコピー → 吹き出しが「確定待ち」表示に変わる
    ↓ 相手がURLを開く
  /demo/r/[id] — 受け取り側ページ（日程選択・所要時間・備考 → 確定 or 別日提案）
    ↓ 確定
  送信者側の吹き出しが「！」表示 → キャラが成長
    ↓ 別日提案
  送信者側に通知 → 新URLを作って送り直す or 手動確定
```

## MVP の範囲

### 含めること（Phase 3 MVP）

**送信者（フォーム）側**:
- ログイン不要でアクセスできる `/demo/farm` または既存 `/farm` を URL パラメータで兼用するかは Generator 判断
- 送信フォーム: 名前・相談内容・希望日程（複数、カレンダーUI + 30分刻み時間選択）
- 送信確認画面: 「今送る」→ URLコピー / 「後で」→ 農園に戻り「未送信」吹き出し表示
- 「後で」状態の保持: ブラウザの localStorage に draft として保存し、キャラタップで再表示できる
- URL送信後の状態変化: 吹き出しが「確定待ち（…）」に変わる
- 相手から返信・確定が来たら吹き出しが「！」に変わる（ポーリングまたはページリロードで検知）
- 返信が別日提案だったとき: 新URLを作り直して送る / 手動確定（「本当に確定しましたか？」確認付き）
- 確定後: キャラが成長する（既存の成長ロジック再利用）

**受け取る側ページ**:
- 既存の `/r/[id]` に以下の機能を追加（変更ではなく**拡張**）:
  - 希望日程から1つを選択（ラジオボタン、既存UIを流用可）
  - 所要時間選択（30分 / 1時間 / 1時間30分 / 2時間 / その他テキスト入力）
  - 備考テキスト入力（任意）
  - 「ミーティング確定」ボタン → 確定後「ミーティングが確定しました！」表示
  - 別日提案: カレンダーUI + 時間（30分刻み）+ 所要時間 + 備考 → 「返信する」ボタン
  - 返信送信後に送信者側へ通知（meetings テーブルに返信データを保存）

**DBマイグレーション**:
- `meetings` テーブルへのカラム追加:
  - `duration_minutes` INTEGER nullable（確定時の所要時間。分単位）
  - `note` TEXT nullable（受け取る側が入力した備考）
  - `alternative_candidates` JSONB nullable（別日提案時の候補日。Candidate[] 形式）
  - `replied_at` TIMESTAMPTZ nullable（別日提案が届いた日時）
  - `manually_confirmed` BOOLEAN DEFAULT false（送信者が手動確定したかどうか）

### 含めないこと

- Push通知・メール通知（URLのポーリングで代替）
- 認証との連携（既存の OAuth ログインフロー変更なし）
- ログイン済みユーザーの農園（`/farm`）への変更（既存のまま）
- 既存の `/r/[id]` の確定ロジック削除（後方互換性を維持）
- WebSocket・リアルタイム更新

## ユーザーフロー

### 送信者フロー

```
農園でキャラをタップ
  ↓
/demo/request/[farm_contact_id] が開く
  ↓
名前・相談内容・希望日程（カレンダーUIで日付選択 + 30分刻み時間選択）を入力
  ↓
「送信」ボタンを押す → meetings テーブルに保存 → URL生成
  ↓
確認画面:「今送りますか？後で送りますか？」
  ├─ 「今送る」→ URLがクリップボードにコピーされる（コピーしました表示）
  │         → キャラの吹き出しが「確定待ち（…）」に変わる
  └─ 「後で」 → localStorage に draft（meeting_id + farm_contact_id）保存
              → 農園に戻る
              → キャラの吹き出しが「未送信」を示す見た目に変わる
              → キャラをタップするとURLを再表示できる

相手から別日提案が届いた場合:
  → 吹き出しが「！」（a6.png）に変わる
  → キャラをタップ → 「返信が届きました」モーダル表示
  → 「新しいURLを作って送り直す」→ 新フォームへ
  → 「手動で確定」→「本当に確定しましたか？」確認ダイアログ → 確定

相手が確定した場合:
  → 吹き出しが「！」（a6.png）に変わる
  → キャラをタップ → 確定日時を表示
  → 確定ボタンを押すとキャラが成長（LEVEL UP演出）
```

### 受け取り側フロー

```
URLを開く（/r/[id]）
  ↓
送信者の名前・相談内容・希望日程一覧が表示される
  ↓
操作選択:
  ├─ 希望日程から1つを選択 → 所要時間を選択（30分/1時間/1時間30分/2時間/その他）
  │   → 備考を入力（任意）→「ミーティング確定」ボタン
  │   → 確定後「ミーティングが確定しました！」表示
  └─ 「別の日を提案する」ボタン
      → カレンダーUIで日付選択 + 30分刻み時間選択 + 所要時間 + 備考
      → 「返信する」ボタン
      → 送信者側に通知（meetings の alternative_candidates / replied_at を更新）
      → 「提案を送りました」表示
```

## 既存仕様との関係

- `/r/[id]` ページは後方互換性を維持しながら機能を追加する
- `/farm` および Phase 2 のログイン済みフローは変更しない
- ログイン不要モードの農園は `/demo/farm` か別ルートで提供（ログイン済み農園と競合しない）
- `meetings` テーブルへの追加カラムはすべて nullable または DEFAULT 値付き（既存データに影響なし）

---

## 技術制約（Generator への引き渡し事項）

- カレンダーUIはライブラリ追加禁止。`input[type=date]` + カスタムUIで実装
- 時間選択は `select` またはボタングループで30分刻み（06:00〜22:00）
- localStorage のキーは `phase3_draft_{farm_contact_id}` 形式
- ポーリングは `setInterval` で10秒〜30秒間隔（コンポーネントがマウントされている間のみ）
- アニメーションは CSS animation のみ（追加ライブラリ禁止）
- `any` を使わない
- `npm run build` が通ること
- 既存の `/r/[id]` ページの確定ロジック（`confirmed_index` 更新）は変更しない
