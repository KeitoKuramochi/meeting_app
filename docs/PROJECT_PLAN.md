# PROJECT_PLAN.md

## アプリの目的

教員とのミーティング日程調整における「候補日のラリー」をなくす。
学生がURLを1つ渡すだけで日程が確定できる状態を作る。

---

## 対象ユーザー

| | 学生 | 教員 |
|---|---|---|
| 役割 | リクエストを作る側 | 日程を確定する側 |
| 技術レベル | スマホ・PC どちらも使える | ブラウザを開ける程度 |
| 利用シーン | ゼミ・卒論相談・質問などの面談申し込み | 届いたURLを開いて選ぶだけ |
| 解決したい課題 | 候補日を出すのが面倒・心理的コストが高い | 何度もメッセージのやり取りをしたくない |

---

## MVPの範囲

**含めること:**
- 学生がフォームで候補日時（3〜5個）と相談内容を入力して送信する
- 固有URLが生成されて表示される（コピーボタン付き）
- 教員がURLを開いて候補日を1つ選んで確定できる
- 確定後はURLを開くと確定日時が表示される
- スマホ幅でも使えるレスポンシブUI

**含めないこと（将来機能）:**
- ログイン・アカウント管理
- メール・Discord・LINE 通知
- リマインダー機能
- 日程の変更・キャンセル
- 教員が複数の候補日を×△○で返す形式
- カレンダー連携

---

## 将来機能（v2以降）

- メール通知（SendGrid等）

- 教員ダッシュボード（複数リクエストを一覧管理）

## 画面一覧

| 画面名 | パス | 説明 |
|---|---|---|
| リクエスト作成 | `/` または `/new` | 学生がフォームを入力する |
| 作成完了 | `/new` 送信後（同ページ内で切り替え） | URLをコピーして先生に送る |
| 確認・確定 | `/r/[id]` | 教員が候補日を選んで確定する |
| 確定済み表示 | `/r/[id]`（確定後） | 確定日時を表示（学生・教員ともに同URL）|

## ユーザーフロー

```
【学生】
アプリを開く（/）
  → 名前・相談内容を入力
  → 候補日時を3〜5個選ぶ
  → 「リクエストを送る」を押す
  → 完了画面でURLをコピー
  → LINEやDiscordで先生にURLを送る
  → あとで同じURLを開いて確定済みかを確認する

【教員】
学生からURLを受け取る
  → URLをブラウザで開く
  → 候補日のリストが表示される
  → 1つ選んで「確定する」を押す
  → 確定完了画面が表示される
```

## DBスキーマ（概念）

`meetings` テーブル:
- `id`: UUID（主キー・URLの一部になる）
- `student_name`: 学生の名前
- `purpose`: 相談内容
- `candidates`: 候補日時の配列（JSONB）
- `confirmed_index`: 確定した候補のインデックス（null = 未確定）
- `confirmed_at`: 確定日時
- `created_at`: 作成日時
