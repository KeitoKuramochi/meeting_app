# REQUIREMENTS.md

## 機能要件

### 必須要件（MUST）

**学生側（リクエスト作成）**
- [ ] 名前（テキスト）を入力できる
- [ ] 相談内容（テキスト）を入力できる
- [ ] 候補日時を最低1個、最大5個まで追加できる
- [ ] 候補日時は「日付」と「時間」を個別に指定できる
- [ ] 候補日時を削除できる
- [ ] 名前・相談内容・候補日時が1個以上ないと送信できない（バリデーション）
- [ ] 送信するとSupabaseにデータが保存される
- [ ] 送信後に固有URL（/r/[id]）が表示される
- [ ] URLをコピーできるボタンがある

**教員側（確定）**
- [ ] URLを開くと学生名・相談内容・候補日時一覧が表示される
- [ ] 候補日時からラジオボタンで1つ選べる
- [ ] 「確定する」ボタンを押すとSupabaseに確定情報が保存される
- [ ] 確定後は確定日時が表示される
- [ ] 確定済みのURLを再度開くと確定日時が表示される（再確定不可）

**エラー・バリデーション**
- [ ] 存在しないIDのURLにアクセスしたとき、エラーページが表示される
- [ ] 空のフォームを送信しようとしたとき、エラーメッセージが表示される

---

### 推奨要件（SHOULD）

- [ ] URLコピー後に「コピーしました」のフィードバックが表示される
- [ ] 送信中・確定中にローディング状態が表示される
- [ ] 候補日時の選択に未来の日付のみ選べるよう制限がある

---

### 任意要件（COULD）

- [ ] 候補日時のソート（早い順）
- [ ] アニメーション・トランジション

---

## 非機能要件

### UI / UX
- スマートフォン幅（375px）でレイアウトが崩れないこと
- ボタン・入力欄は十分なタップ領域（44px以上）を持つこと
- 主要操作（フォーム入力→送信、または候補日選択→確定）は3クリック以内で完了できること
- テンプレート的なAIデザインに偏りすぎず、シンプルで読みやすいUI

### パフォーマンス
- ページの初期表示が体感2秒以内であること

### アクセシビリティ
- `<img>` には `alt` 属性を設定すること
- フォームの `<input>` には `<label>` を紐付けること

### 品質
- `npm run build` がエラーなく通ること
- TypeScriptの型エラーが0件であること
- `any` を使わないこと

---

## 制約

- 外部APIを使わない（Supabase以外）
- 認証不要（URLだけでアクセス可能）
- メール送信・Discord通知はMVPに含めない
- `.env.local` の環境変数はGeneratorが作成しない（人間が設定する）

---

## 用語定義

| 用語 | 定義 |
|---|---|
| リクエスト | 学生が作る日程調整の依頼1件 |
| 候補日時 | 学生が提案するミーティング可能な日時（date + time のペア）|
| 確定 | 教員が候補日時の中から1つを選んで確定した状態 |
| 確認URL | 各リクエストに固有の `/r/[uuid]` 形式のURL |
