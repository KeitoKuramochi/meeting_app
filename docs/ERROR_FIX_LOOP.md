# ERROR_FIX_LOOP.md

> Generator が `npm run build` でエラーに遭遇したときの修正ルールです。
> 最大3回の修正を試みます。3回で直らなければ停止して人間に相談します。

---

## ループの流れ

```
npm run build
  ↓ 成功 → commit へ進む
  ↓ 失敗

[試行 1]
  エラーメッセージを読む
  → 原因を特定する
  → 最小限の修正を行う
  → npm run build
    ↓ 成功 → commit へ進む
    ↓ 失敗

[試行 2]
  エラーメッセージを再度読む
  → 別のアプローチを検討する
  → 最小限の修正を行う
  → npm run build
    ↓ 成功 → commit へ進む
    ↓ 失敗

[試行 3]
  エラーメッセージを再度読む
  → 根本原因を再確認する
  → 最小限の修正を行う
  → npm run build
    ↓ 成功 → commit へ進む
    ↓ 失敗

→ 停止して人間に相談する（STATUS.md のブロッカー欄に記入）
```

---

## 修正時の禁止事項

- エラーを `// @ts-ignore` や `as any` で無視しない
- エラーに関係ないファイルを変更しない
- 大規模リファクタリングで解決しようとしない
- package.json に新しい依存関係を追加して解決しようとしない（人間の許可なし）
- `eslint-disable` でエラーを隠さない

---

## よくあるエラーと対処方針

### TypeScript 型エラー

**原因の特定**:
- エラーが出ているファイルと行番号を確認する
- 型の不一致・未定義のプロパティ・配列の可能性がある `undefined` など

**対処方針**:
- 型定義を修正する（型アサーションで誤魔化さない）
- `undefined` の可能性がある場合は optional chaining やガード節で対処する

### Import エラー

**原因の特定**:
- ファイルパスが正しいか確認する
- named export / default export の不一致を確認する

**対処方針**:
- パスや import 文を修正する

### 未使用変数・型エラー

**原因の特定**:
- `noUnusedLocals`, `noUnusedParameters` の設定を確認する

**対処方針**:
- 変数を使うか、削除する（`_` プレフィクスで意図的に抑制するのは許可）

## 人間への相談テンプレート

3回試みて直らなかった場合、STATUS.md に以下を記入して停止する:

```
## ブロッカー

- TASK ID: TASK-XXX
- エラー内容:
  （エラーメッセージをそのまま貼る）
- 試みた修正:
  1. （修正内容）
  2. （修正内容）
  3. （修正内容）
- 原因の仮説:
  （分かる範囲で）
- 人間へのお願い:
  （何を決定・対処してほしいか）
```
