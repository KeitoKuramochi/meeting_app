# PHASE3_REQUIREMENTS.md — Phase 3 要件定義

作成日: 2026-06-11

---

## 必須要件（MUST）— MVPとして成立するために必要

### 日程入力UI

- MUST-1: 日付は `input[type=date]` を使用し、今日以降の日付のみ選択可能にする（`min` 属性）
- MUST-2: 時間は30分刻みの選択肢（06:00〜22:00）からユーザーが選べる（`select` またはボタングループ）
- MUST-3: 候補日を複数（最低1件、最大5件）入力できる
- MUST-4: 候補日の追加・削除ができる
- MUST-5: 候補日が1件も入力されていない状態で送信しようとするとエラーメッセージが表示される
- MUST-6: 日付か時間のどちらかが未入力の候補は送信時に除外される（空のままでも他に有効な候補があれば送信可能）

### 送信確認フロー

- MUST-7: 送信が完了した直後に「今送りますか？後で送りますか？」の確認画面が表示される
- MUST-8: 「今送る」を選ぶとURLがクリップボードにコピーされ「コピーしました」のフィードバックが表示される
- MUST-9: 「後で」を選ぶと農園ページに戻り、対象キャラの吹き出しが「未送信」を示す見た目に変わる
- MUST-10: 「後で」を選んだ状態でキャラをタップするとURLが再表示される（draft は localStorage に保存）

### 吹き出し状態管理

- MUST-11: 送信後（URLコピー済み）で相手がまだ応答していないキャラの吹き出しは「確定待ち（…）」を示す見た目になる
- MUST-12: 相手から別日提案 or 確定が来たキャラの吹き出しに「！」（a6.png）が表示される
- MUST-13: 吹き出し状態の判定は meetings テーブルのデータに基づく（既存の pendingCount / confirmedCount 拡張で対応）

### 受け取り側ページ拡張

- MUST-14: `/r/[id]` に所要時間選択（30分 / 1時間 / 1時間30分 / 2時間 / その他テキスト入力）を追加する
- MUST-15: 備考テキスト入力欄（任意）を追加する
- MUST-16: 確定ボタンを押すと `confirmed_index`・`confirmed_at`・`duration_minutes`・`note` が meetings テーブルに保存される
- MUST-17: 確定後に「ミーティングが確定しました！」というメッセージが表示される
- MUST-18: 「別の日を提案する」ボタンを追加し、クリックで別日提案フォームが表示される
- MUST-19: 別日提案フォームには日付（input[type=date]）・時間（30分刻み）・所要時間・備考の入力欄がある
- MUST-20: 「返信する」ボタンを押すと `alternative_candidates`・`replied_at` が meetings テーブルに保存される

### DBマイグレーション

- MUST-21: `meetings` テーブルに以下のカラムを追加するマイグレーションSQLファイルを作成する
  - `duration_minutes` INTEGER nullable
  - `note` TEXT nullable
  - `alternative_candidates` JSONB nullable
  - `replied_at` TIMESTAMPTZ nullable
  - `manually_confirmed` BOOLEAN DEFAULT false NOT NULL
- MUST-22: 追加カラムはすべて nullable または DEFAULT 値付きで、既存レコードへの影響がない
- MUST-23: `Meeting` 型に新カラムを追加し `any` を使わない

### 返信受信・手動確定フロー

- MUST-24: 送信者ページで `replied_at` のポーリングを行い、返信が届いたことを検知できる
- MUST-25: 返信が届いたキャラをタップすると「返信が届きました」という表示とともに内容が確認できる
- MUST-26: 「新しいURLを作って送り直す」ボタンで新しいリクエストフォームへ遷移できる
- MUST-27: 「手動で確定する」ボタンを押すと確認ダイアログ（「本当に確定しましたか？」）が表示される
- MUST-28: 確認ダイアログで「はい」を押すと `manually_confirmed = true` が保存され確定扱いになる

### 確定後の成長反映

- MUST-29: `manually_confirmed = true` のミーティングも `confirmed_index IS NOT NULL` のものと同様に confirmedCount としてカウントされる
- MUST-30: 確定後にキャラが成長する（既存の Phase 2 成長ロジックを再利用）

## 推奨要件（SHOULD）— あると体験が良くなる

- SHOULD-1: 時間選択のボタングループは、選択中の時間がハイライトされる
- SHOULD-2: 「後で」状態のキャラと「確定待ち」状態のキャラで吹き出しの見た目が視覚的に異なる
- SHOULD-3: 送信確認画面に候補日の概要（件数）が表示される
- SHOULD-4: 受け取り側で「その他」の所要時間を選んだとき、テキスト入力欄が自動で表示される
- SHOULD-5: 別日提案を送った後、受け取り側に「提案を送りました。相手の返事をお待ちください」と表示される
- SHOULD-6: ポーリング中にユーザーが別タブから戻ったとき、即座に状態を再取得する（Page Visibility API）

---

## 任意要件（COULD）— なくても成立する

- COULD-1: 確定時に確定日をカレンダーに追加するボタン（`.ics` ファイルダウンロード）
- COULD-2: 送信者の候補日が「すべて過去日」になった場合の警告
- COULD-3: 候補日のドラッグ並び替え

## 非機能要件

| 項目 | 要件 |
|---|---|
| スマホ対応 | 375px 幅でレイアウト崩れなし、横スクロールなし |
| タップ領域 | 全ボタンのタップ領域が 44px 以上 |
| 文字サイズ | 全テキストが 14px 以上 |
| ダークモード | `prefers-color-scheme: dark` 対応（Tailwind `dark:` クラス使用） |
| パフォーマンス | ポーリングはコンポーネント unmount 時に `clearInterval` で停止 |
| アクセシビリティ | エラーメッセージに `role="alert"`。時間選択ボタンに `aria-label`。確認ダイアログに適切なロール |
| ビルド品質 | `npm run build` がエラーなく通る。TypeScript の `any` 不使用 |
| 後方互換 | 既存の Phase 1・Phase 2 の動作に影響しない |

## 制約

| 制約 | 理由 |
|---|---|
| カレンダーUIライブラリ追加禁止 | バンドルサイズ削減。`input[type=date]` で十分な機能を提供できる |
| DB追加は既存テーブルへのカラム追加のみ | 新テーブル不要。既存データとの整合性維持 |
| ログイン・認証の新規実装禁止 | Phase 3 はログイン不要モードが前提 |
| 外部API接続禁止 | 通知などは将来フェーズで検討 |
| CSS animationのみ（追加ライブラリ禁止） | 既存実装との統一 |
| `git push` は人間の許可なしに禁止 | 運用ルール（CLAUDE.md）に従う |
